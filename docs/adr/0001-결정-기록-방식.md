# 0001. 결정을 ADR로 기록한다

| 상태 | 날짜 |
|---|---|
| 채택 | 2026-10-06 |

## 맥락
v1을 만들 때 왜 그렇게 정했는지가 코드와 커밋 메시지에만 흩어져 있었다. 나중에 "왜 유니크 제약이 아니라 advisory lock이었나"를 다시 설명하려면 기억에 기대야 했다.

## 결정
기술과 설계를 고를 때마다 `docs/adr/`에 한 장씩 남긴다. 한 장에는 맥락, 결정, 검토한 대안, 결과를 적는다. 채택된 ADR은 고치지 않고 새 ADR로 대체한다.

## 검토한 대안
| 대안 | 장점 | 버린 이유 |
|---|---|---|
| README 한 곳에 모아 쓰기 | 찾기 쉽다 | 결정이 바뀐 흐름이 남지 않는다 |
| 커밋 메시지와 PR 설명만 | 코드와 붙어 있다 | 여러 PR에 걸친 결정을 한눈에 볼 수 없다 |

## 결과
- 결정을 바꿀 때도 이전 결정과 바뀐 이유가 남는다.
- 기록하는 비용이 든다. 한 장은 한 화면 안으로 짧게 쓴다.
