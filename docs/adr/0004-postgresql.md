# 0004. PostgreSQL을 쓴다

| 상태 | 날짜 |
|---|---|
| 채택 | 2026-10-06 |

## 맥락
가장 중요한 규칙은 "시간 구간이 겹치는 예약이 없어야 한다"이다. 이 규칙을 애플리케이션만이 아니라 DB에서도 지키고 싶다. v1도 PostgreSQL이었다.

## 결정
PostgreSQL을 쓴다. 쓰려는 기능:
- 시간 구간 타입 `tstzrange`
- 배타 제약 `EXCLUDE USING gist`: 겹치는 구간을 가진 행 자체를 DB가 거절한다
- 트랜잭션 단위 advisory lock (v1에서 사용)
- 필요하면 Row Level Security로 기관 격리를 한 겹 더 둔다

## 검토한 대안
| 대안 | 장점 | 버린 이유 |
|---|---|---|
| MySQL | 국내 채용 공고에 많다 | 배타 제약이 없다. 구간 겹침을 DB에서 막으려면 잠금과 애플리케이션 검사에 전부 기대야 한다 |

## 결과
- 겹침 규칙을 DB가 최종적으로 보장한다. 애플리케이션에 버그가 있어도 겹친 예약이 저장되지 않는다.
- `btree_gist` 확장이 필요하다.
- 배타 제약은 PostgreSQL 전용이라 다른 DB로 옮기기 어렵다. 옮길 계획은 없다.
