# 0006. 하나의 애플리케이션 안에서 모듈을 나누고 기관별로 켠다

| 상태 | 날짜 |
|---|---|
| 채택 | 2026-10-06 |

## 맥락
기관마다 쓰는 기능이 다르다. 학교는 연습실 예약만 쓰고, 학원은 연습실과 학원 관리를 함께 쓴다. 2차에는 레슨 일정, 청구·결제, 알림이 더해진다.

## 결정
- **코드:** 애플리케이션 하나 안에서 도메인별로 패키지를 나눈다 (기관, 연습실, 학원 관리, 이후 일정·결제·알림). 모듈끼리 허용된 방향으로만 의존하게 하고, ArchUnit 테스트로 검사한다.
- **기관별 켜기:** 기관 설정에 켜진 모듈 목록을 둔다. 꺼진 모듈의 API를 부르면 막는다. 데이터는 지우지 않는다.

## 검토한 대안
| 대안 | 장점 | 버린 이유 |
|---|---|---|
| 모듈마다 별도 서비스 (MSA) | 독립 배포 | 1인 개발, 서버 1대 규모다. 서비스 사이 통신과 분산 트랜잭션 비용만 늘어난다 |
| 패키지를 나누지 않음 | 처음엔 빠르다 | 연습실만 쓰는 기관에 학원 관리 코드가 엉키면 끄고 켜기가 어려워진다 |
| Spring Modulith | 모듈 경계를 프레임워크가 지원한다 | 배울 것이 하나 더 늘어난다. ArchUnit으로 의존 방향만 검사해도 충분하다 |
| 요금제 단위 기능 플래그 서비스 | 유연하다 | 지금은 기관별 켜기·끄기만 있으면 된다 |

## 결과
- 연습실만 쓰는 기관과 전부 쓰는 기관을 같은 코드로 처리한다.
- 모듈 사이에 직접 호출이 필요해지면 의존 방향을 먼저 정해야 한다. 2차의 결제 → 알림처럼 반대 방향이 필요한 경우는 이벤트로 연결한다.
