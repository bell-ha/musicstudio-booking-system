# 0008. PaaS 대신 AWS에 직접 구성한다

| 상태 | 날짜 |
|---|---|
| 채택 | 2026-10-06 |

## 맥락
v1은 DB로 Neon(서버리스 PostgreSQL)을 썼다. Neon의 연결 풀러가 PgBouncer transaction 모드라서, 세션 단위 advisory lock이 다른 연결에서 풀리거나 잠긴 채 반환될 수 있었다. 그래서 트랜잭션 단위 잠금만 쓸 수 있었다.

v2는 동시성 제어 방식들을 같은 조건에서 비교하고 숫자로 남기려 한다. 측정 환경을 통제할 수 있어야 한다. 배포 중 요청이 끊기지 않는지, DB가 외부에 노출되지 않는지도 직접 설계하고 보여 주려 한다.

## 결정
AWS에 직접 구성하고 Terraform 코드로 관리한다.
- VPC: 퍼블릭 서브넷에 EC2, 프라이빗 서브넷에 RDS PostgreSQL
- EC2에서 Docker Compose로 Nginx와 애플리케이션 실행, 블루그린 배포
- GitHub Actions로 테스트, 이미지 빌드, 배포
- SSH 대신 SSM Session Manager, 예산 알림

## 검토한 대안
| 대안 | 장점 | 버린 이유 |
|---|---|---|
| Cloudtype, Render 같은 PaaS | 설정이 거의 없다 | 네트워크 경계와 배포 방식을 다룰 수 없다. 자원을 공유해서 측정이 매번 달라진다 |
| Neon 같은 서버리스 DB | 무료 구간이 있다 | 쉬면 잠들었다 깨어나는 지연이 측정에 섞인다. 연결 풀러 때문에 잠금 동작이 직접 연결과 다르다 (v1 경험) |
| EKS | 확장성 | 관리 비용만 월 약 $73이다. 서버 1대 규모에서 쓸 이유가 없다 |
| 홈서버 | 비용이 거의 없다 | 꺼지면 링크가 죽는다. 클라우드 네트워크를 다룰 수 없다 |

## 결과
- 월 약 $37 (EC2 t4g.small, 공인 IPv4, RDS db.t4g.micro, 서울 리전, 2026-10 기준 대략값).
- DB 운영(백업, 패치)은 RDS에 맡기고, 네트워크와 배포는 직접 설계한다.
- 지원 기간이 끝나면 내리고, 필요할 때 Terraform으로 다시 만든다.
