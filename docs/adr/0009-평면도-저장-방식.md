# 0009. 평면도는 층마다 문서 하나로, 방은 행으로 저장한다

| 상태 | 날짜 |
|---|---|
| 제안 | 2026-10-06 |

## 맥락
관리자가 격자 위에 벽과 복도를 칠하고 방을 배치한다. 학생은 그 지도에서 방을 골라 예약한다. v1은 칠한 칸을 한 칸에 한 행씩 `cells` 테이블에 저장했다.

평면도에 담기는 것은 성격이 두 가지다.
- **벽과 복도:** 그림일 뿐이다. 칸 하나를 따로 조회하거나 다른 테이블이 참조하지 않는다. 저장할 때는 층 전체가 한 번에 바뀐다.
- **방:** 예약이 방을 참조한다. 방 이름, 장비, 점검 상태가 있고, 예약을 조회할 때 조건으로 쓴다.

두 관리자가 같은 층을 동시에 편집할 수 있다.

## 결정
- 층(`floor`) 행에 격자 크기와 **벽·복도 칸 목록을 jsonb 문서 하나**로 저장한다.
- 방(`room`)은 별도 행이다. 층 ID와 격자 위 위치(x, y, 너비, 높이)를 컬럼으로 갖는다.
- 층에 버전 번호를 두고, 저장할 때 읽어 간 버전과 다르면 거절한다 (낙관적 잠금, HTTP `If-Match`).

## 검토한 대안
| 대안 | 장점 | 버린 이유 |
|---|---|---|
| 칸마다 한 행 (v1 방식) | 칸 단위로 조회할 수 있다 | 30×30 층 하나가 최대 900행이다. 저장할 때마다 층 전체를 지우고 다시 넣는다. 칸 단위 조회는 쓰지 않는다 |
| 방까지 jsonb 안에 | 저장이 한 번이다 | 예약이 방을 외래 키로 참조할 수 없다 |
| 이미지 파일 업로드 | 그리기 도구가 필요 없다 | 방을 누르는 동작과 빈 방 표시를 이미지 위에 다시 맞춰야 한다 |

## 결과
- 층 저장이 행 하나의 갱신이 된다.
- 동시 편집을 덮어쓰지 않고 거절한다 (UC-20 대안 흐름 5a).
- jsonb 안의 형식을 애플리케이션이 검증해야 한다. 격자 범위를 벗어난 칸, 방과 겹친 벽 등.
- 구현하며 확인한 뒤 채택으로 바꾼다.
