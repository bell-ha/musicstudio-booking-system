# 0011. 저장소와 백엔드 패키지 구조

| 상태 | 날짜 |
|---|---|
| 채택 | 2026-10-06 |

## 맥락
1인 개발이다. 백엔드, 프론트엔드, 인프라 코드, 부하 테스트, 문서가 모두 필요하다. 백엔드는 모듈(기관, 연습실, 학원 관리)로 나누고 기관별로 켠다 (ADR 0006).

## 결정

### 저장소
한 저장소에 모두 둔다.

```
backend/          Spring Boot (Gradle Kotlin DSL, 단일 모듈)
frontend/         PWA (기술은 나중에 ADR로)
infra/            terraform/, nginx/
load-tests/       k6 시나리오
docs/             requirements/, adr/, architecture/, experiments/, postmortems/, troubleshooting/
docker-compose.yml  로컬 개발용 PostgreSQL
.github/workflows/  CI
```

### 백엔드 패키지
기능 모듈별로 나누고, 모듈 안은 `api / application / domain` 세 단으로 나눈다.

```
com.musicstudio
├── common        에러 응답, 보안, 현재 기관 확인
├── account       계정
├── organization  기관, 멤버, 가입, 모듈 설정
├── practice      연습실 (api / application / domain)
└── academy       학원 관리 (api / application / domain)
```

의존 방향은 아래만 허용하고 ArchUnit 테스트(`ModuleDependencyTest`)로 검사한다.

```
practice ──┐
           ├──▶ organization ──▶ account ──▶ common
academy ───┘
```

- `practice`와 `academy`는 서로 의존하지 않는다.
- `domain`은 `api`, `application`에 의존하지 않는다.
- SQL을 직접 쓰는 코드(겹침 검사, 잠금)가 생기면 그 모듈에만 `infra/`를 더한다.
- 하위 패키지는 그 안에 들어갈 코드가 생길 때 만든다. 빈 패키지를 미리 만들지 않는다.

## 검토한 대안
| 대안 | 장점 | 버린 이유 |
|---|---|---|
| 저장소 분리 (백엔드 / 프론트 / 인프라) | 각자 독립 | 혼자 개발한다. 링크 하나로 전부 보여 주는 쪽이 낫다 |
| 계층별 패키지 (`controller/`, `service/`, `repository/`) | 익숙하다 | 한 기능의 코드가 여러 폴더에 흩어지고, 모듈 경계를 검사할 수 없다 |
| 헥사고날 (포트·어댑터) | 외부 기술과 도메인이 완전히 분리된다 | 이 규모에서는 파일 수만 늘어난다 |
| Gradle 멀티 모듈 | 컴파일 단계에서 경계를 강제한다 | 빌드 설정이 복잡해진다. ArchUnit으로 충분하다. 필요하면 나중에 바꾼다 |
| Maven | 설정이 정형화돼 있다 | Spring 최근 자료와 Initializr 기본값이 Gradle 쪽이다 |

## 결과
- 연습실만 쓰는 기관을 위한 코드와 학원 관리 코드가 섞이지 않는다.
- 의존 방향을 어기면 빌드가 실패한다.
- 기본 패키지 이름 `com.musicstudio`는 임시다. 서비스 이름을 정하면 바꾼다.
