# 0012. 프론트엔드는 React + Vite + TypeScript 정적 웹앱으로 만든다

| 상태 | 날짜 |
|---|---|
| 채택 | 2026-10-06 |

## 맥락
휴대폰 브라우저에서 쓰는 웹앱이다. 앱은 만들지 않는다. 화면은 MVP 기준 10개 정도이고, 평면도 편집기와 지도처럼 화면 안에서 많이 움직이는 기능이 있다. 개발자는 백엔드가 주력이다. v1은 HTML과 JS 파일을 직접 작성했다.

## 결정
- React + Vite + TypeScript로 만들고, 빌드 결과(정적 파일)를 Nginx가 서빙한다.
- 디자인은 저장소 루트의 [DESIGN.md](../../DESIGN.md)를 따른다. 스타일은 그 토큰을 CSS 변수로 두고 직접 쓴다.
- 평면도와 지도는 별도 라이브러리 없이 CSS Grid로 그린다.
- 처음에는 라우터와 서버 데이터 캐시 정도만 들인다. 그 밖의 라이브러리는 필요가 생길 때 넣는다.
- PWA(홈 화면 추가, 웹 푸시)는 2차 알림 기능과 함께 넣는다.
- 아이콘은 lucide 한 벌을 쓴다 (2026-10-06, DESIGN 0.2). 테두리 상자만으로는 "틀에 찍어 낸 화면"처럼 보여서 아이콘 목록 행과 탭 바로 바꿨다.
- 테스트 도구(vitest)는 처음에 넣지 않았다. 화면 없이 검증할 규칙이 생겨서 넣었다 (2026-10-06): 공지·소개의 주소 자동 링크(`splitLinks`)는 한국어 조사, 끝 문장부호, `javascript:` 같은 경계가 많은 순수 함수다. 화면 테스트(E2E)는 아직 넣지 않는다. CI에서 린트, 테스트, 빌드를 돌린다.

## 검토한 대안
| 대안 | 장점 | 버린 이유 |
|---|---|---|
| Next.js | 기능이 많다 | 서버 렌더링이 필요 없는데 Node 서버가 하나 더 생긴다 |
| Thymeleaf (Spring이 화면 렌더링) | 서버 하나로 끝난다 | 평면도 편집기와 지도처럼 화면 안에서 많이 움직이는 기능에 맞지 않는다 |
| v1처럼 HTML과 JS 직접 작성 | 도구가 없다 | 화면이 10개를 넘으면 같은 코드가 반복된다 |
| UI 컴포넌트 라이브러리 | 빨리 만든다 | DESIGN.md의 컴포넌트가 적어서 직접 만들어도 된다. 필요해지면 다시 본다 |

## 결과
- 배포는 정적 파일 복사라서 블루그린 구성(ADR 0008)에 Nginx 설정만 더하면 된다.
- 백엔드와 다른 출처에서 개발할 때 CORS 설정이 필요하다. 운영에서는 Nginx가 같은 도메인으로 묶는다.
