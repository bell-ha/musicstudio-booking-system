# 0015. 기관 로고는 파일 저장소가 아니라 DB(bytea)에 둔다

| 상태 | 날짜 |
|---|---|
| 채택 | 2026-10-06 |

## 맥락
기관 사이트(FR-SITE-01)에서 원장이 로고 이미지를 올린다. 이 서비스에서 처음으로 사용자가 올리는 파일이다. 기관당 1장이고, PNG·JPEG·WebP 200KB 이하로 제한한다.

로고는 앱 바(`<img>`)와 공개 페이지에 보인다. `<img>`는 Authorization 헤더를 보낼 수 없다(토큰이 localStorage에 있다). 운영은 EC2 한 대에서 블루그린으로 컨테이너를 바꾸고, DB는 RDS다 (ADR 0008).

## 결정
- 바이트를 PostgreSQL `site_logo.bytes`(bytea)에 둔다. 기관당 1행(PK = 기관)이고, 바꾸면 덮어쓴다.
- 공개 URL은 `/api/v1/public/logos/{logoKey}`다. `logoKey`는 바꿀 때마다 새로 만드는 무작위 UUID라서, 기관 ID로 훑을 수 없고 `Cache-Control: immutable`로 오래 캐시해도 된다.
- 형식은 Content-Type 헤더가 아니라 파일 앞부분(매직 바이트)으로 확인한다. SVG는 스크립트를 담을 수 있어서 받지 않는다. 디코딩·리사이즈는 하지 않고 화면에서 CSS로 크기를 제한한다.
- 요청 본문은 200KB + 1바이트까지만 읽는다. `@RequestBody byte[]`는 크기와 상관없이 전부 메모리에 올리고, Spring의 `max-request-size`는 multipart에만 적용되기 때문이다.

## 검토한 대안
| 대안 | 장점 | 버린 이유 |
|---|---|---|
| Docker 볼륨(서버 디스크) | 가장 단순하다 | 블루그린에서 두 컨테이너가 같은 디스크를 봐야 하고, EC2를 다시 만들면 사라진다. 백업 경로가 하나 더 생긴다 |
| S3 | 크고 많은 파일에 맞다. CDN을 붙이기 쉽다 | IAM, SDK, 서명 URL, 로컬용 대체(MinIO)가 필요하다. 기관당 200KB 한 장에는 과하다 |
| organization 행에 bytea 컬럼 | 테이블이 하나 준다 | 매 요청 권한 확인에서 읽는 행이 이미지를 끌고 다닌다. 기관 정보와 사이트 정보의 모듈 경계가 흐려진다 |

## 결과
- RDS 스냅숏 하나로 로고까지 백업된다. 로컬 Docker와 EC2에서 똑같이 동작하고, 추가 인프라가 없다.
- 기관 수백 곳이어도 수십 MB다. 이미지 요청이 DB를 거치지만 `immutable` 캐시로 반복 요청은 브라우저에서 끝난다.
- **다시 볼 조건:** 공지 첨부나 레슨 사진처럼 파일이 "기관당 한 장"을 넘으면 S3로 옮긴다. URL이 키 기반이라 `bytes` 컬럼을 S3 키로 바꾸고 응답을 리다이렉트로 바꾸면 된다.
