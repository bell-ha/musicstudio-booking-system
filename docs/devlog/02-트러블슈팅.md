### 1. `FOR UPDATE`로는 겹친 예약이 20건 들어갔다
- **증상:** 같은 방·같은 시각에 동시 요청 1,000건. "겹치는 행을 `SELECT … FOR UPDATE`로 잠그고 없으면 INSERT"가 **20건**을 저장했다.
- **원인:** 아직 없는 행은 잠글 수 없다(phantom). 커넥션 풀 20개를 쥔 트랜잭션이 모두 "없음"을 보고 INSERT했다.
- **해결:** 방·날짜 키로 `pg_advisory_xact_lock` + 마지막 방어선으로 `EXCLUDE USING gist (room_id WITH =, during WITH &&)`. 매번 1건.
- **배운 것:** 행 잠금은 "있는 행"을 지킨다. "없어야 하는 행"을 지키려면 키 잠금이나 제약이 필요하다. → [실험 0001](../experiments/0001-예약-겹침-방지-비교.md), ADR 0010

### 2. 레슨 잠금 키를 다시 읽기 전 값으로 잡았다
- **증상(리뷰 28):** 강사를 바꾸는 요청과 일정을 바꾸는 요청이 동시에 오면 서로 다른 강사 키를 잠그고 둘 다 통과할 수 있었다.
- **원인:** 잠금 키(강사·원생)를 트랜잭션 시작 때 읽은 값으로 만들었다. 잠금을 기다리는 사이 다른 트랜잭션이 강사를 바꾸면 키가 낡는다.
- **해결:** 두 단계 잠금. 수강을 먼저 잠그고 → **다시 읽은 뒤** → 강사·원생을 id 오름차순으로 잠근다(교착 방지). 먼저 실패하는 결정적 테스트를 썼다: JDBC 연결 두 개로 한쪽이 잠금을 쥔 상태를 만들고 `pg_locks`에서 대기를 확인한 뒤 진행.
- **배운 것:** 잠금 키는 잠금 뒤에 읽은 값이어야 한다. 동시성 테스트는 sleep이 아니라 "상대가 기다리는 중"을 DB에서 확인하고 진행해야 매번 같은 결과가 난다.

### 3. 휴강 처리가 잠그지 않은 회차까지 바꿨다
- **증상(리뷰 28):** 그날 전체 휴강(cancel-day)이 잠금을 잡지 않은 수강의 회차까지 바꿨다.
- **해결:** 잠근 수강의 회차만 처리하고, 잠그지 못한 것은 건너뛴 목록으로 돌려준다. 테스트에서 일부러 잠금을 빼 실패하는지 확인(돌연변이 확인).

### 4. `CHECK`의 OR 분기에서 NULL이 통과했다
- **증상:** 횟수권/기간권 어느 쪽 값도 없는 상품이 저장됐다.
- **원인:** SQL의 3값 논리. `CHECK (a > 0 OR b > 0)`에서 둘 다 NULL이면 결과가 NULL이고, CHECK는 NULL을 통과로 본다.
- **해결:** 분기마다 `IS NOT NULL`을 명시.

### 5. 수강 id가 null이 아니라 0으로 나갔다
- **증상(리뷰 32):** 직접 만든 청구서(교재비)의 `enrollmentId`가 화면에 0으로 왔다.
- **원인:** `rs.getLong()`은 NULL을 0으로 준다. `wasNull()`을 다른 컬럼을 읽은 뒤에 불러서 엉뚱한 컬럼을 검사했다.
- **해결:** `rs.getObject("enrollment_id", Long.class)`.

### 6. 한글 비밀번호 30자로 가입하면 500
- **원인:** BCrypt는 72**바이트**까지만 받는다. 한글은 UTF-8로 3바이트라 30자가 90바이트.
- **해결:** 글자 수가 아니라 바이트 길이를 검증해서 400으로.

### 7. 만료된 토큰을 단 채 로그인하면 401
- **원인:** 브라우저가 남은 Bearer 토큰을 로그인 요청에도 붙였고, 리소스 서버 필터가 먼저 검증해 거절했다.
- **해결:** 인증 경로(`/auth/**`)에서는 Bearer를 읽지 않는다.

### 8. 기관 id "06"으로 모듈 검사를 건너뛰었다
- **원인:** 인터셉터가 요청 URI 문자열로 모듈을 판단했다. 같은 기관을 가리키는 다른 표기("06", "+6")나 경로 표기 차이로 URI 비교가 어긋나면 모듈 검사를 건너뛸 수 있었다.
- **해결:** 원래 URI가 아니라 매칭된 핸들러 경로 패턴(`BEST_MATCHING_PATTERN_ATTRIBUTE`)으로 모듈을 판단하고, 기관 id는 `Long.toString(id).equals(raw)`인 표준 표기만 받는다(아니면 404).
- **배운 것:** 권한 판단은 "사용자가 보낸 문자열"이 아니라 "프레임워크가 실제로 고른 핸들러"를 기준으로.

### 9. 남의 이메일로 먼저 가입하면 구글 로그인을 가로챌 수 있었다 (설계 단계)
- **시나리오:** 공격자가 피해자 이메일로 비밀번호 계정을 만들어 둔다 → 피해자가 구글로 로그인 → 같은 이메일이라 자동 연결 → 공격자도 그 계정에 들어간다(사전 계정 탈취).
- **해결:** 이메일이 같아도 자동 연결하지 않는다. 연결은 로그인한 상태에서 "구글 계정 연결"로만. → ADR 0013

### 10. 구글이 느리면 DB 커넥션을 쥔 채 기다렸다
- **원인:** `@Transactional` 메서드 안에서 구글 토큰 교환(외부 HTTP)을 불렀다.
- **해결:** 검증을 트랜잭션 밖으로, 연결·읽기 타임아웃 5초.
- **배운 것:** 트랜잭션 안에는 DB 일만. 외부 호출은 밖에서.

### 11. Jackson 3에서 빠진 boolean 필드가 400
- **원인:** Spring Boot 4의 Jackson 3는 원시 `boolean` 필드가 요청에 없으면 실패한다(기본값 false로 채우지 않음).
- **해결:** 선택 필드는 `Boolean`으로 두고 null을 처리.

### 12. record의 계산 메서드가 JSON에 안 나왔다
- **증상:** 청구서 응답에 `balance`(남은 돈)가 없었다.
- **원인:** Jackson은 record의 **컴포넌트**만 직렬화한다. 따로 만든 `balance()` 메서드는 무시.
- **해결:** `balance`를 컴포넌트로 넣고 만들 때 계산.

### 13. 10:00 예약이 "01:00"으로 보였다
- **원인:** 겹침 오류 응답의 시각이 UTC `Instant`로 나갔다.
- **해결:** 모든 응답 시각을 기관 시간대 오프셋(`+09:00`)으로. 시간대는 IANA 이름만 받는다(`UTC+9` 같은 오프셋은 PostgreSQL `AT TIME ZONE`에서 부호가 반대로 해석될 수 있음).

### 14. 이전 응답이 새 결과를 덮었다
- **증상:** 예약 지도·레슨 일정에서 날짜를 빠르게 넘기면 늦게 온 이전 날짜 응답이 화면을 덮었다.
- **해결:** `useEffect`마다 `let current = true`, 정리 함수에서 false. 지난 요청의 응답은 버린다.

### 15. 글씨 겹침·한글 줄바꿈·로고 잘림
- **찾은 방법:** Playwright로 모든 화면의 글자 영역(Range rect)을 모아 서로 겹치거나 화면 밖으로 나가는 것을 자동으로 찾는 스크립트(360px·1440px).
- **고친 것:** 로그인·가입 부제가 제목과 겹침(`margin-top`), 평면도 편집기 방 이름 넘침, 한글이 단어 중간에서 끊김(`word-break: keep-all` + `overflow-wrap: anywhere`), 가로로 긴 DKU 로고가 정사각 틀에서 잘림(높이 고정·너비 자동).
- **오탐:** 말줄임(…)과 줄 수 제한(line-clamp)으로 숨긴 글자도 Range에는 잡힌다. 검사기에서 걸러야 한다.

### 16. MinIO 이미지를 받을 수 없었다
- **증상:** Docker Hub의 `minio/minio` pull 실패, quay.io는 401, bitnami 이미지는 없어짐.
- **해결:** 같은 S3 API를 주는 **SeaweedFS**(`chrislusf/seaweedfs:4.48`)로. 코드는 AWS SDK v2의 S3 API만 쓰므로 바꿀 것이 없었다. → ADR 0017

### 17. SeaweedFS가 서명 요청을 거절, 준비 대기가 끝나지 않았다
- **원인 1:** SeaweedFS는 `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` 환경 변수가 있어야 인증을 켠다. 없으면 SDK의 서명 요청과 맞지 않았다.
- **원인 2:** Testcontainers의 준비 확인이 200을 기다렸는데, 인증을 켠 S3 루트는 403을 준다.
- **해결:** 컨테이너에 키 환경 변수, 대기 조건은 `forStatusCodeMatching(code -> code < 500)`. 기본 포트도 MinIO의 9000이 아니라 8333(리뷰 31).

### 18. 테스트 도우미 `status()`가 MockMvc의 것을 가렸다
- **증상:** 테스트 클래스에 만든 `status()` 때문에 `status().isOk()`가 컴파일되지 않거나 엉뚱한 것을 불렀다.
- **해결:** 도우미 이름을 `code()`로.

### 19. 쓸 기능을 하나도 안 고르면 기본 기능이 켜졌다
- **증상(온보딩 교차 리뷰):** 기관을 만들 때 모듈을 빈 목록으로 보내면 서버가 유형 기본값을 켰다. 기관 설정(UC-03)에서는 빈 목록이 "아무것도 안 씀"이라 두 화면의 뜻이 달랐다.
- **해결:** `null`(안 보냄)일 때만 기본값, 빈 목록은 그대로. 테스트 추가.

### 20. 일정을 과거부터 정해도 지난 회차가 생기지 않았다 (데모 데이터)
- **원인:** 의도된 동작. 일정 저장은 `now` 이전 회차를 만들지 않는다(지난 출결을 지어내지 않게).
- **해결(데모 한정):** 지난 회차를 SQL로 넣고, 횟수권은 같은 수만큼 맨 뒤 미래 회차를 지워 "총 회차" 불변식을 맞춘 뒤 출결은 API로 남겼다.

### 21. VS Code에서 backend 폴더가 빨간색
- **원인:** 코드 오류가 아니라 Java 확장이 처음 읽은 의존성 목록을 계속 썼다. 나중에 추가한 Spring Security·OAuth2 라이브러리를 몰라 "찾을 수 없음" 114개.
- **해결:** `Java: Reload Projects`, 안 되면 `Java: Clean Java Language Server Workspace`. Gradle 빌드와 CI는 처음부터 정상.

### 22. 옮겨 둔 v1 평면도가 안 보였다
- **원인:** v1 평면도를 다른 데모 계정이 만든 기관에 넣고, 사용자는 다른 계정으로 보고 있었다.
- **해결:** 그 계정을 해당 기관의 소유자로 추가. 데모 계정과 기관의 관계를 기록(아래 질문과 답)해 두기로.

### 23. Docker를 다시 켰는데 화면이 안 열렸다
- **증상:** postgres·storage·backend는 올라왔는데 :3000이 응답 없음.
- **원인:** frontend 컨테이너가 전에 정지(Exited 0)된 상태였다. `restart: unless-stopped`는 **직접 멈춘 컨테이너는 다시 켜지 않는다.**
- **해결:** `docker compose --profile full up -d`.

### 24. IDE 빌드 결과 `backend/bin/`이 커밋됐다 (열려 있음)
- **원인:** VS Code Java 확장이 `backend/bin/`에 컴파일 결과를 쓰는데 `.gitignore`에 없었다.
- **할 일:** `git rm -r --cached backend/bin`, `.gitignore`에 `bin/` 추가.

### 25. OAuth 비밀값을 채팅에 붙여 넣었다 (열려 있음)
- 비밀값은 git에 없고 `.env`(gitignore)에만 있다. 하지만 채팅 기록에 남았으므로 **배포 전에 GCP 콘솔에서 새 비밀값을 발급**하고 `.env`를 바꾼다.
